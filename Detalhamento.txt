RELATÓRIO TÉCNICO E ARQUITETURAL - PROJETO DE DETECÇÃO IFTO (VERSÃO 2.1)

ARQUITETURA DO PROJETO E FLUXO DE TRABALHO (PIPELINE)

O projeto opera em uma arquitetura híbrida de Nuvem/Borda (Cloud-Edge) dividida em dois ambientes principais, explorando ao máximo a capacidade assíncrona dos hardwares disponíveis:

NUVEM (Google Colab): Responsável pelas rotinas massivas de Big Data. A GPU Tesla T4 (16GB VRAM) executa o Auto-Labeling, divisão dos bancos de dados, geração nativa '.txt' (YOLO) e treinamento profundo (Deep Learning).

BORDA (PC AMD Ryzen 3 / RX 580): Responsável pela inferência de alta performance em tempo real via aplicação Desktop (PyQt5). Projetado especificamente para rodar o runtime ONNX, compensando a ausência de núcleos CUDA locais.

ESTRATÉGIA DE MODELAGEM (TEACHER-STUDENT)

Aplica-se o paradigma avançado de Destilação de Conhecimento (Teacher-Student):

Professor (Anotador): O modelo YOLOv8m.pt processa os frames e gera coordenadas precisas baseadas nos pesos originais treinados na base COCO (80 classes), rastreando a classe Bolsa (IDs 24 e 26).

Aluno (Modelo Final IFTO): A arquitetura mais moderna, YOLO11 Nano (yolo11n.pt), "herda" essas anotações (agora compactadas em uma classe única, ID 0) e realiza um Fine-Tuning intensivo, tornando-se especialista (Specialist Model) para rodar leve na máquina de borda.

PIPELINE DE TREINAMENTO OTIMIZADO V2 (Nuvem)

FP16 (Precision Scaling): Utiliza-se 'half=True' durante as rodadas de treino, otimizando transistores e cortando até 30% do tempo de processamento matricial na Tesla T4.

Forçamento de GPU Local (device=0): Bloqueia o uso da CPU para treinamento.

Data Augmentation Agressivo (YOLO Loader): Mutações efetuadas exclusivamente em RAM por lote.

Mosaic=1.0: Concatenação de quatro imagens para aprendizado holístico;

Degrees=15.0 / Translate=0.1: Rotação e correção de oclusão do corredor do IFTO;

Fliplr=0.5 / Scale=0.5 / hsv_s=0.3: Mutação de iluminação e aproximação das catracas.

ACELERAÇÃO DE INFERÊNCIA E COMPILAÇÃO (ONNX EDGE COMPUTING)

A solução para taxas baixas de FPS no Windows/Ryzen baseia-se na conversão e roteamento de APIs:

Exportação ONNX: O PyTorch original 'best.pt' sofre um freeze graph conversion gerando 'best.onnx'. Esse formato (Open Neural Network Exchange) dispensa as pesadas bibliotecas de treinamento da máquina local.

ONNX Runtime Execution: O aplicativo de monitoramento injeta o ONNX diretamente na engine C++ em vez de instanciar a classe Python Ultralytics padrão, aumentando drasticamente o processamento de Tensores na CPU AMD.

APLICATIVO DE MONITORAMENTO LOCAL (app_monitoramento.py - OTIMIZADO)

O novo script PyQt5 consolida as melhores práticas de Engenharia de Interface em Python:

Contenção de Vazamento e Crash: Variáveis de ambiente isolam as diretrizes do processador (KMP_DUPLICATE_LIB_OK e ORT_DISABLE_MEMORY_PATTERN), eliminando crashes crônicos no Windows com OpenMP.

Execução Assíncrona Não-Bloqueante (QThread): A interface gráfica (Janela) é desvinculada do loop pesadíssimo do OpenCV/YOLO, permitindo fluidez extrema nos botões e mostradores.

Resolução Dinâmica Segura: Redimensionamento matricial 'Aspect-Ratio safe' (KeepAspectRatio + SmoothTransformation) efetuado pós-inferência, alimentando o processador de vídeo visual (QPixmap) sem achatamento.

Lógica Condicional de Classes:

'best.pt' / 'best.onnx': ID 0 é interpretado e traçado estritamente como "Bolsa" (Vermelho).

'yolo11n.pt' genérico: Retoma Mapeamento COCO: ID 0 = "Pessoa" (Verde), IDs 24/26 = "Bolsa" (Vermelho).

Fila Circular (Deque): Implementação rigorosa do cálculo de Quadros Por Segundo com buffer deslizante para exibição numérica na Barra de Status sem oscilação estroboscópica visual.
